## 2. 공통 근본원인 — 하나다

6건 중 5건(030·031·032·033·035)은 **전부 같은 층의 문제**다.
실험A만 유일하게 **공유·가변·영구 누적되는 실제 Postgres 원천**을 측정 대상으로 쓴다.

실험 B·C·D는 `data/benchmarks/fixtures/` 아래에 매번 새로 만드는 합성 Fixture를 쓴다. 상태가 없다.
실험A는 같은 형태로 설계됐지만 실제로는 운영 Ingestion의 불변식을 그대로 상속한다:

- `BatchIdentity(dag_id, logical_date)` 멱등 재사용
- Watermark CAS와 Lease
- `rewind_watermark`의 엄격 부등호
- `cursor_before_timestamp`의 엄격 `<`
- **원천에 쓴 행은 지워지지 않는다**

여섯 번의 수정은 사실상 이 목록을 한 줄씩 발견해 온 과정이다.

## 3. 설계 초기 검토가 부족했나 — 그렇다

숨길 이유 없이 적는다. 초기 설계(`docs/superpowers/specs/2026-09-21-phase9-benchmark-design.md`)는
Ingestion 모듈의 **공개 API 표면**(`ingest_table`, `rewind_tables`, `run_generator`가 존재하고 조합 가능하다)을
보고 실험A를 조립했다. 그 API들이 **강제하는 불변식**과 **원천 DB의 실제 상태**는 확인하지 않았다.
`SELECT COUNT(*), MIN(updated_at), MAX(updated_at) FROM orders` 한 번이면 032는 설계 단계에서 나왔다.

다만 정직하게 나눠 보면:

- **설계 검토 부족**: 030, 032, 033, 035 (4건). 전부 사전에 확인 가능했다.
- **내 판정 오류**: 034 (1건). 033 §4에서 불변식을 상태가 아니라 메커니즘으로 적었다.
- **직렬 은폐**: 031. 030을 고치기 전에는 도달조차 못 하는 지점이었다.

여기에 검출 지연이 겹쳤다. 유일한 검출기가 30~51분짜리 종단 실행이었고, 앞선 결함이 뒤의 결함을
가렸다(크래시 → Hash 검사 도달 못 함 → Watermark Gate 도달 못 함 → Anchor 충돌 도달 못 함).
그래서 한 번에 하나씩만 드러났다.

## 4. 035로 안정화됐다고 보는 근거

**"안정화됐다"고 단언하지 않는다. 035는 아직 한 번도 실행되지 않았다.** 근거는 코드 추론뿐이다.
그 전제 위에서, 035가 앞의 다섯과 다른 점은 다음이다.

1. **가정을 계산으로 바꾼 첫 수정이다.** 030~033·035 이전 수정은 깨진 가정을 다른 가정으로 교체했다
   (033 §2의 "t0는 항상 최신이다"가 대표적이다 — 그게 035에서 깨졌다).
   035는 `t0 = max_existing + 1분`으로 **원천에서 값을 읽어 계산한다.** 한 실행의 `t1`이 다음 실행의
   `max_existing`이 되므로 단조 증가가 구조적으로 보장된다. 이 실패 경로는 가정이 아니라 산술로 닫힌다.
2. **각 실패마다 대응 검출기가 남았다.** 지금 4층이 깔려 있다:
   Batch Identity 분리(030) / Watermark 사후 조건 검사(034) / `result_hash` Arm 동등 Gate(기존) /
   Anchor 사전 조건 검사(035). 035의 검사는 **Setup 51분 이전**에 돈다.
3. **반복 비용이 내려갔다.** XS(500 order) 사전 검증 경로가 생겼고, 035가 1시간 재시도 간격 제약을
   없앴다. 결함 하나 발견에 51분이 아니라 몇 분이 든다.

## 6. 권고 — 반복에 정지 규칙을 건다

지금까지 없었던 것이 **중단 기준**이다. 6회를 돈 이유의 일부가 여기 있다.

1. 재개하면 **XS 사전 검증부터** 한다. S Scale은 XS가 5/5 `VALID`(Hash 일치)를 낼 때까지 돌리지 않는다.
2. **XS에서 원천 상태 계열의 새 결함이 한 번 더 나오면 점진 수정을 멈춘다.** 그 시점에 선택지는 두 개다.
   - (가) 실험A를 Phase 9 범위에서 내리고, 얻은 것을 "실제 Ingestion 경로 벤치마크의 전제조건"
     문서로 정리해 한계로 명시한다. 실험 B·C·D는 이미 측정 가능하다.
   - (나) 원천 격리 비용(035 §대안 3에서 반려한 것)을 정식 범위로 승격해 일정을 다시 잡는다.
3. 어느 쪽이든 **lead 판단 사항**이다. architect가 혼자 7번째 수정으로 넘어가지 않는다.
